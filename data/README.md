출퇴근 10분 = 하루 10단어 = **20일치**.

## 파일이 겹쳐 쌓입니다 ★

같은 `hsk_id` 가 여러 파일에 있는 건 **정상입니다.**

```
words-l3-101-973.csv        了  liǎo  동사  (한국어 뜻 없음)
words-l3-freq-101-200.csv   了                다 ~할 수 있다 + 예문
                            ─────────────────────────────────
결과                        了  liǎo  동사  다 ~할 수 있다 + 예문
```

**규칙: 값이 있는 쪽이 이깁니다.** 빈 칸은 앞서 읽은 값을 덮지 않아요.

그래서 뼈대 파일을 몇 번을 다시 돌려도 한국어 뜻이 지워지지 않습니다. 순서도 신경 쓸 필요 없고요.

:::note[같은 파일 안에서 겹치면 에러입니다]
파일끼리 겹치는 건 설계고, 한 파일 안에서 겹치는 건 실수라서 구분해서 처리합니다.
:::

## 다음 100개는 어떤 기준으로 고르나

**빈도 순위가 낮은 것부터** — 자주 쓰는 말부터입니다.

앞의 100개(`001-100`)는 빈도 데이터가 생기기 전이라 가나다순으로 잘랐습니다. 지금은 `frequency` 칸이 있어서, 아직 뜻이 없는 단어 중 자주 쓰는 것부터 골라 쓰고 있어요.

```sql
select id, hanzi, pinyin, frequency
from public.words
where meaning_ko is null
order by frequency asc nulls last
limit 100;
```

`daily_words()` 도 같은 기준으로 골라줍니다. 그래서 **화면을 열면 제일 흔한 단어부터 나옵니다.**

:::caution[뜻과 예문은 아직 검수 전입니다]
| | 믿을 수 있나 |
|---|---|
| `hsk_id` · `hanzi` · `pinyin` · `pos` | **예.** 공식 목록 원본 그대로 |
| `meaning_ko` · 예문 3칸 | **아직.** 새로 만든 것 |

테스트 베드로 쓰기엔 충분합니다. 다만 문법에 맞아도 중국 사람은 안 쓰는 문장일 수 있고, 성조가 틀렸을 수도 있어요. 사이트가 굴러가기 시작하면 하루 잡고 훑으세요.
:::

## 칸 10개

| 칸 | 설명 | 비어도 되나 |
|---|---|---|
| `hsk_id` | **공식 목록 번호. 기본 키.** `L3-0004` | X |
| `hanzi` | 간체자 | X |
| `pinyin` | 성조 기호 포함 (`juédìng`) | X |
| `pos` | 품사 | O |
| `level` | HSK 급수. 지금은 전부 `3` | X |
| `meaning_ko` | 한국어 뜻. 여러 개면 ` · ` 로 구분 | X |
| `topic` | 주제 | O |
| `example_zh` | 예문 (간체자) | O |
| `example_pinyin` | 예문 병음 | O |
| `example_ko` | 예문 해석 | O |

예문 3칸은 **셋 다 있거나 셋 다 없거나** 로 하세요. 하나만 있으면 화면이 어색해집니다.

:::note[`hanzi` 는 겹칠 수 있습니다 — 정상입니다]
공식 목록에 같은 한자가 두 번 나와요.

| 한자 | |
|---|---|
| `把` | L3-0006 개사(~을) / L3-0007 양사(자루) |
| `背` | L3-0028 bēi 업다 / L3-0030 bèi 등 |

그래서 기본 키가 `hanzi` 가 아니라 `hsk_id` 입니다. 한자로 묶으면 이 넷이 **에러 없이 조용히** 둘로 줄어듭니다.
:::

## 값 안에 쉼표를 쓰지 마세요

CSV는 쉼표로 칸을 나눕니다. 값 안에 쉼표가 들어가면 칸이 밀려요.

| 이렇게 말고 | 이렇게 |
|---|---|
| `Tā huì shuō Hànyǔ, bìngqiě...` | `Tā huì shuō Hànyǔ bìngqiě...` |

중국어 문장 부호(`，`, `。`, `？`)는 **써도 됩니다.** 반각 쉼표(`,`)만 피하시면 돼요.

## 파일을 열 때 · 꼭 지킬 것

:::danger
**엑셀로 이 파일을 열고 저장하지 마세요.**

엑셀은 CSV를 한국어 윈도우 기본 인코딩으로 읽어서 한자와 병음 성조 기호를 망가뜨립니다. 저장하는 순간 원본이 진짜로 깨지고, 되돌릴 수 없습니다.
:::

**안전한 방법 3가지**

| | |
|---|---|
| VSCode에서 직접 열기 | 오른쪽 아래에 `UTF-8` 이라고 떠 있으면 안전 |
| 구글 스프레드시트 | 만들고 → 파일 → 다운로드 → CSV |
| 엑셀을 꼭 써야 하면 | 저장할 때 **"CSV UTF-8"** 형식 선택 |

**확인법:** 저장한 뒤 VSCode로 다시 열어서 한자와 `é` `ì` 같은 글자가 멀쩡한지 보세요.

## Supabase에 올릴 때 · CSV 업로드를 쓰지 마세요

Table Editor 화면에 CSV 업로드 기능이 있지만 **그 방식은 멱등하지 않습니다.** 같은 파일을 두 번 올리면 줄이 200개가 돼요.

대신 SQL로 넣습니다. [../db/README.md](../db/README.md) 에 순서가 있고, 10분이면 끝납니다.

```sql
insert into public.words (...) values (...)
on conflict (hsk_id) do update set ...
```

이 방식은 **몇 번을 돌려도 100줄**입니다. 뜻이나 예문을 고쳤을 때도 표를 지울 필요 없이 다시 돌리면 반영돼요.

**넣고 나서 반드시 눈으로 확인하세요.**

```sql
select hsk_id, hanzi, pinyin, meaning_ko from public.words order by hsk_id limit 10;
```

`爱心` / `àixīn` 처럼 한자와 성조 기호가 멀쩡해야 합니다. 이 확인을 건너뛰고 973개를 넣었다가 깨져 있으면 전부 다시 해야 합니다.
