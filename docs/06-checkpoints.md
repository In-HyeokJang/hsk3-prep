# 어디가 문제인가 · 어디를 고치나

> 회차마다 **"이게 되면 통과"** 와, 안 될 때 **"어느 파일을 보는지"** 를 정리했습니다.
> 막혔을 때 이 파일부터 여세요.

---

## 진단하는 순서

막혔을 때 이 순서로 좁힙니다. **위에서부터.**

| 순서 | 물어볼 것 | 아니면 |
|---|---|---|
| 1 | 화면이 아예 안 뜨나? | → **A. 안 켜짐** |
| 2 | 뜨는데 내용이 비었나? | → **B. 데이터** |
| 3 | 내용은 있는데 눌러도 안 되나? | → **C. 기능** |
| 4 | 다 되는데 이상하게 보이나? | → **D. 보기** |
| 5 | 로컬은 되는데 배포본만 안 되나? | → **E. 배포** |

**순서를 건너뛰지 마세요.** 1번이 안 됐는데 3번을 고치면 시간만 갑니다.

## A · 화면이 안 켜짐

| 증상 | 어디가 문제 | 이렇게 말하세요 |
|---|---|---|
| 빨간 글씨만 좌르르 | 대부분 설치가 덜 됨 | 에러 처음 5줄 그대로 붙여넣기 |
| `localhost:3000` 이 안 열림 | 서버가 안 켜짐 | `npm run dev 를 실행했는데 주소가 안 보여` |
| 3000번 포트가 이미 쓰인대요 | 아까 켠 게 안 꺼짐 | `3000번 포트가 이미 사용 중이래. 어떻게 해?` |
| 화면이 하얗게 비어 있음 | 코드는 돌고 화면만 빔 | `화면이 하얗게 비어 있어. 뭘 확인해야 해?` |

**에러 프롬프트 틀**
```
이 명령어를 실행했는데 에러가 났어:
npm run dev

에러 메시지야:
[빨간 글씨 처음 5줄 붙여넣기]

뭐가 문제인지, 뭘 확인해야 하는지 알려줘.
```

## B · 데이터가 안 나옴 (이 프로젝트에서 제일 많이 만날 것)

### 단어 목록이 비어 있음

이 순서로 확인하세요. **위에서부터 하나씩.**

| 확인 | 어떻게 |
|---|---|
| 1. Supabase에 진짜 데이터가 있나 | Supabase 화면 → Table Editor → `words` 열어보기 |
| 2. 테이블 이름이 맞나 | 코드가 `words` 를 부르는데 테이블이 `word` 면 안 됩니다 |
| 3. 칸 이름이 맞나 | `meaning_ko` 인데 코드가 `meaning` 을 부르면 빈칸 |
| 4. 키가 맞나 | `.env` 안의 URL·키가 Supabase 화면 값과 같은지 |
| 5. RLS가 막고 있나 | 데이터는 있는데 안 나오면 대부분 이것 |

**5번이 제일 많이 걸립니다.**

```
Supabase 테이블에 데이터는 들어 있는데 사이트에서는 목록이 비어 나와.
에러 메시지는 안 떠.
RLS 정책 때문일 수 있어? 어디를 보면 되는지 알려줘.
```

### 한자가 `?` 나 네모로 보임

**두 가지 중 하나입니다. 구분부터 하세요.**

| 이렇게 보이면 | 원인 | 고치는 곳 |
|---|---|---|
| `??` 또는 `锟斤拷` 같은 깨진 글자 | **데이터가 깨짐** (CSV 인코딩) | 원본 CSV. 테이블을 지우고 다시 올려야 함 |
| □ 네모 또는 글자 모양이 어색 | **폰트 문제** | 화면 코드. 중국어 폰트 지정 |

**구분하는 법:** Supabase 화면의 Table Editor에서 한자가 제대로 보이면 → 폰트 문제. 거기서도 깨져 있으면 → 데이터가 깨진 것.

:::danger[데이터가 깨졌으면 그 상태로 진행하지 마세요]
973개를 다 넣고 나서 발견하면 전부 다시 넣어야 합니다.

**100개 넣고 눈으로 확인한 다음** 나머지로 넘어가세요.
:::

### 병음 성조가 사라짐

`juédìng` 이 `juding` 이나 `juedeng` 으로 보이면 인코딩 문제입니다. 위와 같은 원인이에요.

## C · 눌러도 아무 일이 안 남

| 증상 | 대개 이것 | 이렇게 말하세요 |
|---|---|---|
| 버튼을 눌러도 반응 없음 | 3회차엔 정상 | 4회차 프롬프트로 |
| 눌리는데 새로고침하면 사라짐 | 저장이 화면에만 됨 | `새로고침해도 남아 있게 해줘` |
| **두 번째 누를 때 `duplicate key` 에러** | **`insert` 로 만들어짐** | 바로 아래 |
| `violates foreign key constraint` | `word_id` 값이 `words` 에 없음 | `progress 에 넣는 word_id 가 words 의 id 에 있는 값인지 확인해줘` |
| `violates check constraint "progress_status_check"` | `status` 에 엉뚱한 값 | `status 는 new / unknown / learning / known 넷 중 하나여야 해` |
| 저장은 되는데 다른 브라우저에서 안 보임 | `user_key` 가 달라서 | **정상입니다.** 로그인이 없으니까요 |
| 진도를 지우려는데 안 지워짐 | **일부러 막아둔 것** | 정상입니다. `01-schema.sql` 에 delete 정책이 없어요 |
| "저장됐어요" 는 뜨는데 Supabase엔 없음 | **가장 위험한 증상** | 아래 참고 |

### `409 duplicate key value violates unique constraint`

**4회차에 가장 많이 만날 에러입니다. 실제로 확인했습니다.**

`upsert` 로 바꿔도 계속 납니다. **`onConflict` 를 안 적었기 때문**이에요.

`progress` 의 기본 키는 `id`(자동 UUID)인데, 겹침을 막는 건 `unique (user_key, word_id)` 입니다. Supabase는 `onConflict` 가 없으면 기본 키를 기준으로 삼는데, `id` 는 매번 새로 만들어지니 안 겹칩니다. 그래서 그냥 `insert` 처럼 굴다가 터져요.

```
진도 저장이 두 번째 클릭에 409 duplicate key 로 터져.
upsert 를 쓰고 있는데도 그래.

onConflict 를 지정해줘:
supabase.from('progress').upsert(줄, { onConflict: 'user_key,word_id' })
```

| 확인 | 정상이면 |
|---|---|
| 첫 번째 클릭 | `201` |
| 두 번째·세 번째 클릭 | `200` (`409` 아님) |
| `select count(*) from progress` | 클릭을 몇 번 하든 **1줄** |

:::note[이 에러는 좋은 에러입니다]
제약이 없었다면 에러 없이 줄이 계속 쌓였을 거예요. 그러면 "외웠어요"를 열 번 누른 단어가 진도에 열 번 세어집니다.

**에러가 났다는 건 표가 제 역할을 했다는 뜻입니다.**
:::

### `204` 가 떴는데 아무것도 안 바뀜 — 이건 정상입니다

`words` 를 고치거나 지우려 하면 **에러가 아니라 `204` 가 돌아옵니다.** 그런데 데이터는 그대로예요.

권한에 막히면 "거절"이 아니라 **"고칠 수 있는 줄이 0개"** 로 처리되기 때문입니다. 그래서 응답만 보면 성공한 것처럼 보입니다.

:::danger[상태 코드는 증거가 아닙니다]
`site-notes.md` 에 적어두신 그 교훈이 여기서도 그대로입니다.

> *"성공을 알리는 기준은 서버가 200을 줬는가가 아니다."*

**확인하는 법:** 요청 뒤에 실제로 다시 읽어보세요.

```sql
select count(*) from public.words;                          -- 100 이면 안 지워짐
select meaning_ko from public.words where id = 'L3-0001';   -- 원래 값이면 안 바뀜
```
:::

:::danger[성공 메시지를 믿지 마세요]
`site-notes.md` 에 이미 겪으신 그 문제입니다. 저장에 실패했는데 화면에는 "저장됐어요"가 뜨는 경우요.

> *"사용자에게 성공을 알리는 기준은 서버가 200을 줬는가이지, 코드가 에러 없이 끝났는가가 아니다."*

**확인법:** 뭔가 저장한 다음 Supabase 화면을 새로고침해서 **진짜로 줄이 늘었는지** 눈으로 보세요.

```
저장 버튼을 누르면 "저장됐어요" 가 뜨는데 Supabase 테이블에는 안 들어가 있어.
서버 응답을 확인하고, 진짜 저장됐을 때만 성공 메시지가 뜨게 고쳐줘.
```
:::

**5회차 전이면 전부 정상입니다.** 메모만 해두세요.

한자 자형만 예외인 이유는 [04-prompts.md](04-prompts.md) 의 3회차 ③에 적어뒀습니다. 이건 디자인이 아니라 **글자가 틀린 것**이라서요.

## E · 로컬은 되는데 배포본만 안 됨

**이건 거의 항상 환경 변수입니다.** `site-notes.md` 에 이미 정리돼 있어요.

> `import.meta.env` / `process.env` 값은 **빌드할 때** 코드 안으로 박힙니다.
> 로컬은 `.env` 를 읽지만, 배포 서버에는 `.env` 가 없습니다.

| 확인 | 어디 |
|---|---|
| Vercel에 환경 변수를 넣었나 | Vercel → 프로젝트 → Settings → Environment Variables |
| 이름이 정확히 같나 | 한 글자라도 다르면 빈 값입니다 |
| 넣고 나서 다시 배포했나 | **넣기만 하면 반영 안 됩니다.** 재배포해야 합니다 |

```
Vercel에 배포했는데 사이트에서 단어 목록이 안 나와.
로컬에서는 잘 됐어.
환경 변수 이름이 뭐로 되어 있어야 하는지 알려줘.
```

## 회차별 통과 기준

여기까지 되면 그 회차는 끝난 겁니다. **더 하지 마세요.**

### 3회차 통과

- [ ] 맨 위 메뉴로 홈·단어장·학습을 다 갈 수 있다
- [ ] 홈에서 단어 카드를 누르면 상세로 넘어간다
- [ ] 상세에서 "목록으로"를 누르면 단어장으로 온다
- [ ] 가짜 단어 3개가 화면에 있다
- [ ] 한자가 중국어 폰트로 보인다
- [ ] 브라우저 탭 이름이 "Create Next App" 이 아니다
- [ ] GitHub에 올라가 있다

### 4회차 통과 (세 갈래 다 정상)

| 어디까지 | |
|---|---|
| **폼까지** | 버튼이 생겼고 눌러진다 |
| **화면까지** | 눌리면 표시가 바뀐다. 새로고침하면 사라짐 |
| **연결 성공** | 새로고침해도 표시가 남아 있다 |

**셋 다 4회차의 정상입니다.**

### 5회차 통과

- [ ] 폰 화면에서 안 깨진다
- [ ] 한자가 충분히 크다
- [ ] `npm run build` 가 에러 없이 끝난다
- [ ] GitHub에 올라가 있고 `.env` 는 안 올라갔다

### 6회차 통과

- [ ] 인터넷 주소로 열린다
- [ ] 그 주소를 폰으로 열어도 단어가 나온다 ← **여기가 진짜 확인**
- [ ] 남에게 링크를 보내도 열린다

:::caution[6회차에는 반드시 폰으로 확인하세요]
노트북 브라우저에서만 확인하면 놓치는 게 있습니다. 폰에서 열어야 폰트·줄바꿈·환경 변수 문제가 한꺼번에 드러나요.
:::
