### ④ progress 연결 — 이 프롬프트가 중요합니다

```
이제 progress 테이블도 연결해줘.

로그인은 안 만들 거야. 브라우저에 UUID를 하나 만들어 저장해두고,
그 번호(user_key)로 내 진도를 구분해줘.

지킬 것:
- 저장할 때 insert 말고 upsert 를 써줘. 그리고 onConflict 를 꼭 지정해줘.

  supabase.from('progress').upsert(줄, { onConflict: 'user_key,word_id' })

  onConflict 를 안 적으면 기본 키(id)를 기준으로 삼아서
  두 번째 누를 때 duplicate key 409 에러가 나. 실제로 확인했어.
- status 에 들어갈 수 있는 값은 new / unknown / learning / known 넷뿐이야.
  다른 값을 넣으면 제약에 걸려.
- 저장이 성공했는지 서버 응답을 확인하고,
  진짜 성공했을 때만 화면에 표시를 바꿔줘.

"외웠어요"를 누르면 progress 에 저장되고,
새로고침해도 표시가 그대로 남아 있게 해줘.
```

:::danger[`onConflict` 를 빠뜨리면 반드시 터집니다 — 실제로 확인했습니다]
`progress` 의 기본 키는 `id`(자동 생성 UUID)이고, 겹침을 막는 건 `unique (user_key, word_id)` 입니다. **둘이 다릅니다.**

Supabase는 `onConflict` 를 안 적으면 **기본 키**를 기준으로 삼아요. 그런데 `id` 는 매번 새로 만들어지니 절대 안 겹치고, 그래서 그냥 `insert` 처럼 굴다가 `unique` 제약에 걸립니다.

| 어떻게 부르나 | 결과 |
|---|---|
| `onConflict` 없이 | 첫 번째 `201` → **두 번째 `409 duplicate key`** |
| `onConflict: 'user_key,word_id'` | 첫 번째 `201` → 두 번째 `200` → 세 번째 `200`. 줄은 계속 1개 |
:::

:::caution[나머지 두 줄도 이유가 있습니다]
| 줄 | 안 넣으면 |
|---|---|
| status 값 4개 | `"외움"` 같은 한글을 넣어서 제약에 걸림 |
| 서버 응답 확인 | 저장 실패해도 "됐어요"가 뜹니다 |

두 번째는 `site-notes.md` 에서 이미 겪으신 그 문제예요.
:::

