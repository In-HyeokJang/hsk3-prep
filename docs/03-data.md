# 자료 준비 가이드 ★

> **이 프로젝트에서 유일하게 AI가 대신 못 해주는 부분입니다.**
> 3회차 시작 전까지 끝내두세요.

---

## 먼저 · 이 프로젝트가 다른 프로젝트와 다른 점

커뮤니티에 나오는 예시들(카페 기록, 산책 코스, 포트폴리오)은 **내용이 내 머릿속에 있습니다.** 카페 이름을 내가 알고 있으니 그냥 치면 돼요.

HSK 사이트는 다릅니다. **600단어가 내 머릿속에 없어요.**

| | 카페 기록 사이트 | HSK 사이트 |
|---|---|---|
| 내용을 누가 아나 | 내가 안다 | **밖에서 가져와야 한다** |
| 틀리면 | 내 기록이 틀린 것 | **공부하는 사람이 잘못 외운다** |
| 몇 개 필요한가 | 3개면 화면이 나옴 | 3개로도 화면은 나오지만 사이트가 안 됨 |

그래서 이 프로젝트는 **"자료 준비"가 별도의 회차**라고 생각하셔야 합니다.

## 지금 결정해야 할 것 3개

이건 AI가 정해줄 수 없습니다. 정하고 오셔야 그다음이 굴러가요.

### 결정 1 · 어느 기준의 3급인가 → **정해졌습니다**

**신 HSK 3.0 기준으로 갑니다.**

교육부·국가언어문자업무위원회가 2021년에 낸 《국제중문교육 중문수준 등급표준》이 기준입니다.

| 급수 | 그 급수의 단어 수 | 누적 |
|---|---|---|
| 1급 | 500 | 500 |
| 2급 | 772 | 1,272 |
| **3급** | **973** | **2,245** |

**3급 단어는 973개.** 이 숫자는 추정이 아니라 확인된 값입니다 — 공식 표준 원문에서 뽑은 단어 목록의 3급 행이 정확히 973개이고, 북경어언대 출판사의 공식 《词汇速记速练手册·三级》 소개도 "共973词"라고 적고 있습니다.

> 구 HSK 2.0의 "3급 = 600단어"와는 다릅니다. 한국 교재 중에는 아직 2.0 기준인 것이 많으니, 나중에 교재를 고르실 때 어느 기준인지 확인하세요.

**자료 출처:** 공식 PDF를 정리해둔 공개 저장소 [ivankra/hsk30](https://github.com/ivankra/hsk30) 의 `hsk30.csv` 에서 `Level = 3` 인 행을 뽑았습니다. 한자·병음·품사는 이 목록 그대로이고, **한국어 뜻과 예문은 새로 만든 것**입니다.

---

### 결정 2 · 예문을 어디서 가져오나

이게 **법적으로 조심해야 할 유일한 부분**입니다.

| 출처 | 써도 되나 |
|---|---|
| 단어 목록 자체 (한자·병음) | 공개 표준이라 대체로 문제없음 |
| **교재의 예문을 그대로 옮기기** | **하지 마세요.** 남의 저작물입니다 |
| **기출 문제를 그대로 옮기기** | **하지 마세요.** 더 위험합니다 |
| 내가 직접 만든 예문 | 문제없음 |
| AI가 만들고 내가 검수한 예문 | 문제없음. **검수가 조건입니다** |

**권하는 방법:** AI에게 예문을 만들게 하고, 중국어를 아는 사람이 한 번 훑습니다.

:::caution[AI가 만든 중국어 예문은 반드시 검수하세요]
AI는 문법에 맞지만 중국 사람은 안 쓰는 문장을 만들 때가 있어요. 성조 기호도 틀립니다.

**공부하는 사이트에서 틀린 예문은 그냥 버그가 아니라 피해입니다.** 사용자가 틀린 걸 외워요.

600개를 다 검수하기 어려우면, **처음엔 50개만 넣고 시작하세요.** 검수한 만큼만 올리는 게 맞습니다.
:::

### 결정 3 · 몇 개로 시작하나 → **100개로 정해졌습니다**

출퇴근 10분 = 하루 10단어. **100개면 10일치**입니다. 테스트 베드로 딱 맞아요.

| 몇 개 | 언제 | 상태 |
|---|---|---|
| **100개** | 1단계 · 출퇴근 10분용 | **준비 완료** |
| 973개 전체 | 2단계 · 1단계가 2주 굴러간 뒤 | [08-roadmap.md](08-roadmap.md) |

**3회차에 973개를 넣지 마세요.** 화면이 안 뜨는데 데이터가 많으면 뭐가 문제인지 못 찾습니다.

**어떤 100개인가:** 공식 목록 앞에서부터 `L3-0001` ~ `L3-0100`. 병음 가나다순(音序)이라 **다음 100개가 자명합니다.** 공식 학습서도 같은 순서로 20개씩 묶어 하루치를 만들어요.

> 나중에 "자주 쓰는 단어부터"로 순서를 바꾸고 싶으면, 빈도 데이터를 붙여서 다시 정렬하면 됩니다. 지금은 하지 마세요.

## 자료 형식

| 파일 | 뭐가 |
|---|---|
| `data/words.sample.csv` | 20단어 형식 견본 (형식 설명용) |
| **`data/words-l3-001-100.csv`** | **실제로 쓸 100단어** |

| 칸 이름 | 뭐가 들어가나 | 예 |
|---|---|---|
| `hsk_id` | **공식 목록 번호. 기본 키** | L3-0004 |
| `hanzi` | 간체자 | 按 |
| `pinyin` | 성조 기호 붙은 병음 | àn |
| `pos` | 품사 | 동사·개사 |
| `level` | HSK 급수 | 3 |
| `meaning_ko` | 한국어 뜻 | 누르다 · ~에 따라 |
| `topic` | 주제 (묶어보기용) | 동작 |
| `example_zh` | 예문 (간체자) | 请按这个按钮。 |
| `example_pinyin` | 예문 병음 | Qǐng àn zhège ànniǔ. |
| `example_ko` | 예문 해석 | 이 버튼을 눌러 주세요. |

:::note[`hsk_id` 가 기본 키인 이유 — 이게 멱등성의 핵심입니다]
공식 목록에 **같은 한자가 두 번** 나옵니다.

| 한자 | |
|---|---|
| `把` | L3-0006 개사(~을) / L3-0007 양사(자루) |
| `背` | L3-0028 bēi 업다 / L3-0030 bèi 등 |

한자를 키로 잡으면 이 넷이 둘로 줄어듭니다. **에러 없이 조용히 사라지기 때문에** 눈치채기도 어려워요.

`hsk_id` 는 공식 번호라 바뀌지 않습니다. 그래서 같은 자료를 몇 번 다시 넣어도 100줄 그대로입니다.
:::

:::caution[CSV를 엑셀로 열면 한자가 깨집니다]
엑셀은 CSV를 열 때 한국어 윈도우 기본 인코딩으로 읽어서, **한자와 병음 성조 기호가 `??` 나 이상한 글자로 바뀝니다.**

그 상태로 저장하면 **원본이 진짜로 망가집니다.** 되돌릴 수 없어요.

**안전한 방법**
- 구글 스프레드시트에서 만들고 → 파일 → 다운로드 → CSV (자동으로 UTF-8)
- 또는 VSCode에서 직접 열고 편집 (오른쪽 아래에 `UTF-8` 이라고 떠 있는지 확인)

엑셀을 꼭 써야 하면 저장할 때 **"CSV UTF-8"** 형식을 고르세요.
:::

## Supabase → **SQL이 이미 준비돼 있습니다**

화면에서 클릭으로 만들지 않습니다. **SQL 파일 세 개를 순서대로 붙여넣고 Run 하면 끝**입니다.

| 파일 | 뭘 |
|---|---|
| `db/01-schema.sql` | 표 4개 · 보기 1개 · 함수 1개 · 권한 |
| `db/02-seed-words.sql` | 단어 100개 |
| `db/03-seed-examples.sql` | 예문 100개 |

하는 법은 [../db/README.md](../db/README.md) 에 순서대로 있습니다. 10분이면 끝나요.

:::note[왜 클릭이 아니라 SQL인가]
커리큘럼 4회차에는 "화면에서 클릭으로, SQL 안 씁니다"라고 적혀 있습니다. 카페 리뷰 표 하나면 그게 맞아요.

그런데 이 프로젝트는 **표가 2개고, 둘이 서로 연결돼 있고, 자료를 여러 번 다시 넣게 됩니다.** 클릭으로 하면 매번 손이 가고, 무엇보다 **같은 CSV를 두 번 올리면 줄이 두 배가 됩니다.**

SQL 파일로 해두면 몇 번을 돌려도 결과가 같습니다. 그리고 붙여넣고 Run 하는 건 클릭보다 오히려 쉬워요.
:::

### 표 4개 + 보기 1개

| | 뭐가 | 지금 |
|---|---|---|
| `words` | 단어. PK는 `id` (`L3-0001`) | 100줄 |
| `examples` | 예문. 단어 하나에 여러 개 가능 | 100줄 |
| `progress` | 내 진도. 사람마다 단어마다 한 줄 | 0줄 |
| `attempts` | 푼 기록. 게임·통계용 | 0줄 |
| **`v_words`** | **보기.** 단어 + 대표 예문을 한 줄로 | — |

:::note[예문을 왜 표로 뺐나 — 그런데 앱은 안 복잡해집니다]
지금은 단어 하나에 예문 하나지만, **1시간용으로 키우면 서너 개가 필요해집니다.** 그때 `words` 에 `example_zh_2`, `example_zh_3` 을 붙이기 시작하면 손을 못 써요.

대신 `v_words` 라는 보기를 만들어뒀습니다. **화면에서는 표 두 개를 붙일 필요 없이 `v_words` 하나만 읽으면 됩니다.** 예문이 늘어나도 이 보기는 그대로 대표 예문 하나만 줘요.

> 화면 코드는 안 바뀌고 데이터만 자란다 — 이게 표를 나눈 이유입니다.
:::

### `progress` — 내 진도

| 칸 이름 | 뭐가 들어가나 |
|---|---|
| `user_key` | 브라우저마다 다른 임시 번호 |
| `word_id` | 어느 단어인지 |
| `status` | `new` / `unknown` / `learning` / `known` |
| `seen_count` `correct_count` `wrong_count` | 몇 번 봤고 몇 번 맞고 틀렸는지 |
| `due_at` | 다음에 다시 볼 시각 (지금은 비워둠) |

**`user_key` 가 로그인을 대신합니다.** 처음 사이트에 들어오면 브라우저에 아무 번호를 하나 만들어 저장해두고, 그 번호로 내 진도를 구분해요.

| | |
|---|---|
| 좋은 점 | 회원가입 화면·비밀번호·로그인 에러가 전부 없어짐 |
| 한계 | 폰에서 보던 진도가 노트북에는 안 나옴. 브라우저 기록을 지우면 진도도 사라짐 |

혼자 쓰는 사이트라 이 한계는 감수할 만합니다. 4회차 난이도를 크게 낮춰줘요.

:::caution[진도 저장은 `insert` 가 아니라 `upsert` 입니다]
`progress` 에 `unique (user_key, word_id)` 제약을 걸어뒀습니다. **한 사람이 한 단어에 한 줄.**

그래서 4회차에 AI에게 이 말을 꼭 해야 합니다.

```
진도를 저장할 때는 insert 말고 upsert 를 써줘.
progress 테이블에 unique (user_key, word_id) 제약이 이미 걸려 있어.
```

**안 하면** 버튼을 두 번 누르는 순간 `duplicate key` 에러가 납니다.
:::

:::caution[삭제는 막아뒀지만 완전하지는 않습니다]
`site-notes.md` 에 적어두신 그 문제입니다. anon 키가 사이트에 그대로 박히는 구조요.

`01-schema.sql` 에서 **`progress` 삭제 권한을 아예 안 만들어뒀습니다.** 누가 장난쳐도 기록이 지워지지는 않아요.

다만 읽는 것까지는 못 막습니다. 로그인이 없어서 서버가 주인을 확인할 수 없거든요. **남에게 링크를 주기 전에는 익명 로그인을 붙여야 합니다** — [08-roadmap.md](08-roadmap.md) 2단계.
:::

## 자료 만드는 프롬프트

**100개는 이미 만들어져 있습니다.** 아래는 2단계에서 973개로 늘릴 때 쓰세요.

**한 번에 973개를 시키지 마세요.** 20~30개씩 끊습니다.

**단어 목록 자체는 지어내게 하지 마세요.** 공식 목록 원본에서 뽑고, AI에게는 **뜻과 예문만** 시킵니다.

```
공식 HSK 3.0 목록에서 뽑은 단어야. 한자·병음·품사는 이미 정해져 있어.
여기에 한국어 뜻과 예문만 붙여서 CSV로 만들어줘.

[여기에 hsk_id, hanzi, pinyin, pos 붙여넣기]

칸은 이 순서 그대로:
hsk_id, hanzi, pinyin, pos, level, meaning_ko, topic, example_zh, example_pinyin, example_ko

지킬 것:
- hsk_id, hanzi, pinyin 은 준 값을 그대로. 절대 고치지 마
- 예문은 HSK 3급 수준의 짧은 문장으로. 10글자 안팎
- 예문 병음도 성조 기호를 붙여서 (jue2ding4 나 jueding 아님)
- 一 와 不 의 성조 변화를 반영할 것 (yí ge, bú zài 처럼)
- 값 안에 쉼표를 쓰지 마. CSV가 깨져
- 확실하지 않으면 지어내지 말고 그 줄을 비워둬

이번에는 [101번부터 120번까지] 만들어줘.
파일은 data/words-l3-101-120.csv 로 저장해줘.
```

:::note[왜 20개씩 끊나요]
한 번에 많이 시키면 뒤로 갈수록 대충 만듭니다. 병음 성조가 틀리기 시작해요.

그리고 20개는 **내가 눈으로 검수할 수 있는 양**입니다. 973개는 못 봐요.
:::

## 정리 · 누가 뭘 하나

| 하는 일 | 누가 | 상태 |
|---|---|---|
| 어느 기준의 3급인지 결정 | 나 | 완료 (3.0 · 973단어) |
| 단어 목록 원본 확보 | AI | 완료 (공식 목록에서 추출) |
| 100단어 뜻·예문 만들기 | AI | 완료 |
| 테이블 DDL · 시드 SQL | AI | 완료 |
| **중국어 예문·성조·뜻 검수** | **나 또는 중국어 아는 사람** | **아직** |
| SQL을 Supabase에서 실행 | 나 (붙여넣고 Run) | 아직 |
| 화면·기능·디자인·배포 | AI | 3회차부터 |

**굵은 줄 하나만 남았습니다.** 그런데 그 하나가 제일 중요해요.

:::caution[100개는 아직 검수 전입니다]
한자·병음·품사는 공식 목록 그대로라 믿을 수 있습니다.

**한국어 뜻과 예문은 새로 만든 것이라 검수가 필요합니다.** 문법에 맞아도 중국 사람은 안 쓰는 문장일 수 있고, 성조가 틀렸을 수도 있어요.

지금은 테스트 베드니까 이 상태로 진행하셔도 됩니다. 다만 **"이건 아직 검수 전"이라는 걸 알고 쓰는 것과 모르고 쓰는 건 다릅니다.** 사이트가 굴러가기 시작하면 그때 하루 잡고 훑으세요.
:::
