### 만들면서 실제로 터진 것

| | 무슨 일이 있었나 |
|---|---|
| **버튼 안의 버튼** | 보기(`<button>`) 안에 스피커(`<button>`)를 넣으면 **스피커를 눌렀는데 답이 선택**됩니다. 틀린 기록이 남고 복습이 3분 뒤로 당겨집니다. 결과 화면의 '놓친 것' 목록(`<Link>`)에서도 같은 함정을 또 만났습니다 |

| | 무슨 일이 있었나 |
|---|---|
| **뜻이 같은 보기** | `把`(자루·손잡이) 문제에 `支`(자루·가늘고 긴 것)가 보기로. **정답이 둘.** 괄호 안 설명이 달라서 통과했습니다. 괄호를 지우고 견주게 고쳐서 **68쌍 → 0쌍** |
| **가입이 조용히 실패** | 같은 아이디로 다시 가입하면 Supabase 가 **에러 없이** 가짜 사용자(`identities: 0`)를 돌려줍니다. 화면에 아무 말도 안 나왔습니다 |
| **음높이 옥타브 오류** | 220Hz 를 **73Hz(3분의 1)** 로 읽었습니다. 배음 때문에 두세 주기를 밀어도 잘 겹칩니다. "제일 잘 겹치는 곳" 이 아니라 **"거의 같은 높이의 첫 봉우리"** 를 고르게 고쳤습니다 |
| **`为 · 为` 가 나란히** | 한자 가족에서. 공식 목록에 `为`(동사)/`为`(개사)가 따로 있어서요. 한자 기준 하나만 남깁니다 |
| **별표가 일정을 밀어냄** | 안 본 단어에 별표만 눌러도 그 단어가 **오늘의 1번**으로 튀어나왔습니다. `due_at` 이 빈 줄을 "제일 오래 밀림" 으로 봤기 때문입니다. **"아직 일정 없음"** 으로 고쳤습니다 |

## 이 프로젝트만의 중요한 구조

### 아이디는 내부적으로 가짜 주소가 됩니다

```
hong1234  →  hong1234@hsk3.local
```

**화면에는 절대 안 나옵니다.** `web/lib/useAuth.ts` 의 `loginEmail()` 과
`supabase/migrations/20260804080000_username.sql` 이 짝입니다. **한쪽만 고치면 안 됩니다.**

### 확인 메일을 안 보냅니다

`hong1234@hsk3.local` 로는 메일을 받을 수 없습니다.
마이그레이션 9가 계정이 만들어지는 순간 "확인 끝난 계정" 으로 표시합니다.
**Supabase 대시보드에서 Confirm email 을 켜도 이 트리거가 이깁니다.**

### 비밀번호를 잊으면

이제 **스스로 바꾸는 화면은 있습니다** (홈 → 설정). 하지만 **잊었을 때 되찾는 길은 없습니다.**
재설정 메일을 보낼 곳이 없어서요. 문의가 오면 Supabase SQL Editor 에서:

```sql
update auth.users
   set encrypted_password = extensions.crypt('새비밀번호', extensions.gen_salt('bf'))
 where email = 'hong1234@hsk3.local';
```

### 탈퇴한 계정을 되살리려면

```sql
update public.profiles set is_active = true, deleted_at = null
where username = 'hong123';
```

진도는 이미 지워졌으니 처음부터 시작합니다. 아이디만 되살아납니다.

### 신고 들어온 것 보기

```sql
select * from public.reports where not handled order by created_at desc;
update public.reports set handled = true, handled_at = now() where word_id = 'L3-0001';
update public.words   set verified = true, verified_at = now() where id = 'L3-0001';
```

`npm run db:audit` 이 이것도 같이 보여줍니다.

### 못 보낸 진도는 브라우저에 쌓입니다

지하철에서 신호가 끊기면 `web/lib/pending.ts` 가 받아둡니다.
연결되면 알아서 보냅니다. 화면에는 "N개를 아직 못 보냈어요" 가 뜹니다.

**별표는 여기 안 들어갑니다.** 다시 누르면 그만이고, 나중에 몰아 보내면
순서가 꼬여 껐던 별표가 되살아나는 쪽이 더 나쁩니다.

## 다시 밟으면 안 되는 지뢰

전부 실제로 한 번씩 겪은 것들입니다.

| | 어떻게 되나 | 어떻게 피하나 |
|---|---|---|
| `progress` 를 `insert` 로 저장 | 두 번째 클릭에 `409` | `mark_word` 함수를 씀 |
| `v_words` 를 그냥 `drop` | `cannot drop view ... depend on it` | `drop view ... cascade` |
| 마이그레이션을 한 번만 돌려보고 넘어감 | **두 번째 실행에서만** 터짐 | 고친 뒤 반드시 두 번 연속 실행 |
| Tailwind `@theme` 을 미디어 쿼리 안에 | 낮에도 밤에도 어두운 화면 | `@media` 안에서는 `:root` 로 변수만 다시 정의 |
| 고쳤는데 화면이 그대로 | 옛 서버가 예전 빌드를 주고 있음 | 서버를 껐다 켠다 |
| CSV 값 안에 반각 쉼표 | 칸이 밀림 | 중국어 문장부호(`，`)는 괜찮고 `,` 만 피함 |
| `204` 를 성공으로 읽기 | 권한에 막혀도 성공처럼 보임 | 바꾼 뒤 **다시 읽어서** 확인 |
| **useEffect 신호에 `statusOf`·`progress`·학습량 넣기** | 답을 저장할 때마다 카드가 다시 만들어져 **1번 문제로 되돌아감** | ref 에 담아 쓰기 |
| **RLS 로 칸을 막으려 함** | RLS 는 줄 단위만 막습니다 | 칸 단위는 `grant update (칸이름)` |
| **에러를 안 보고 `data` 만 씀** | 신호가 끊기면 "없다" 로 읽혀서 확인 장치가 뚫림 | `error` 를 먼저 확인 |
| **저장될 때까지 다음으로 안 넘김** | 지하철에서 1번 문제에 갇힘 | 못 보낸 것을 적어두고 넘어가기 |
| `example.com` 으로 가입 시험 | Supabase 가 거부 | 실제 도메인 모양을 쓰기 |
| **`status` 로 먼저 거르기** | 애써 정한 `due_at` 이 통째로 무시됨 | 복습은 **시각 하나만** 보고 정하기 |
| **오답을 정답하고만 비교** | 보기 네 개 중 둘이 같은 말 | 이미 고른 오답과도 견주기 |
| **괄호까지 통째로 견주기** | `자루(손잡이)` / `자루(가늘고 긴 것)` 이 서로 다른 뜻으로 통과 | 괄호를 지우고 견주기 |
| **버튼 표시를 퀴즈 정답으로 기록** | 연타 네 번에 복습이 35일 뒤로 | 손으로 누른 것은 따로 취급 |
| **중요한 것을 폰 화면에서 숨기기** | 서로 다른 단어가 같은 줄로 보임 | `hidden sm:inline` 전에 "폰에서 없어도 되나" 묻기 |
| **에러가 없으면 성공으로 읽기** | 가입이 조용히 실패해도 화면에 아무 말이 없음 | 돌려받은 것을 뜯어보기 |
| **자기상관에서 제일 큰 봉우리 고르기** | 220Hz 를 73Hz 로 읽음 | 거의 같은 높이의 **첫** 봉우리 |
| **`due_at` 이 빈 줄을 "제일 오래 밀림" 으로 보기** | 별표만 눌러도 오늘의 1번으로 튀어나옴 | 빈 것은 "아직 일정 없음" |
| **저장소(localStorage) 값을 믿기** | 손으로 고친 `9999` 가 서버로 넘어감 | 목록에 없는 값은 기본값으로 |
| **늘 "없음" 만 말하는 검사** | 검사가 있는데 아무것도 안 잡힘 | 일부러 틀린 줄을 넣어 잡히는지 보기 |
| **버튼·링크 **안에** 버튼 넣기** | 스피커를 눌렀는데 **그 보기가 선택**되어 틀린 기록이 남고 복습이 3분 뒤로. 링크면 화면이 넘어가 소리를 못 들음 | 감싸는 `div` 가 테두리를 갖고 **형제**로 두기 |
| **보기·문제에 소리를 붙이기** | `pick-py` 는 소리가 곧 정답이고, 성조 문제는 TTS 가 답을 읽어줌 | 붙이기 전에 **"이 소리가 답을 알려주나"** 를 묻기 |
| **`ǜ` 의 성조를 떼며 `u` 로** | 绿(lǜ)가 路(lù)로 되살아남 | `ǜ → ü`. `pinyin.ts` 의 R 시험이 지킵니다 |
| **한자가 겹치는 단어를 병음으로만 거르기** | 背 문제의 보기에 `bēi`·`bèi` 가 같이 떠서 **정답이 둘**. 한자가 겹치는 여섯 쌍 중 **셋은 병음이 다릅니다**(背·调·精神) | 병음만이 아니라 **한자도** 견주기 |
| **뽑기(랜덤)가 든 검사를 한 번만 돌리기** | 5회차에 "같은 한자 보기 0" 이었는데 이번에 1건. 그때 안 걸렸을 뿐입니다 | 여러 바퀴 돌려서 세기 (8바퀴 77,840문제) |
| **되돌릴 수 없는 답을 한 탭에 받기** | 오탭 하나에 틀린 기록 · 연속 정답 끊김 · 복습이 35일 뒤 → 3분 뒤. **되돌릴 길이 없습니다** | 진도를 바꾸는 답은 **두 번 묻기**. 안 바꾸는 답(`/tone`)은 한 번에 |
| **화면이 바뀌는 자리에 잠금이 없음** | 앞 화면의 버튼과 새 화면의 버튼이 **같은 자리**라, 연타의 두 번째 탭이 새 화면 버튼을 누름 | 새 화면이 뜬 뒤 **300ms 는 조용히 무시**. `disabled` 로 만들면 초점이 튕겨나갑니다 |
| **확인 버튼을 화면 맨 아래에 두기** | 거기는 채점 뒤 '다음' 이 오는 자리입니다. 연타하면 **정답 카드를 못 보고 넘어갑니다** | 같은 자리에서 한 번 더 누르게 하기 (손가락이 안 움직임) |
| **갱신 함수 안에서 다른 상태를 바꾸기** | `setA(prev => { setB(...) })`. React 는 갱신 함수를 **두 번 부를 수 있어서** 단어가 두 칸씩 뛰고 점수가 2점씩 깎입니다. **7회차에만 세 번** 밟았습니다 | 한 덩어리 상태로 합치거나, 지금 값을 그냥 읽어서 바깥에서 바꾸기 |
| **같은 성질의 Tailwind 클래스를 둘 붙이기** | `opacity-40` 과 `opacity-0` 을 같이 쓰면 **뒤에 쓴 것이 안 이깁니다.** 만들어진 CSS 차례로 이겨서 늘 40이 남습니다 | 삼항으로 **하나만** 내보내기 |
| **키를 `window` 에서 받고 `preventDefault`** | 입력 칸에서 `Backspace` 가 안 지워지고 숫자 키가 다른 일을 합니다 | `INPUT`·`TEXTAREA`·`contenteditable` 에서 온 키는 흘려보내기 |
| **가운데 정렬한 칸에 `overflow-y-auto` 를 같이 걸기** | 내용이 칸보다 커지면 **위쪽이 잘려나가고 그 위로는 스크롤이 안 올라갑니다.** 아래로만 굴러가서, 머리줄 밑으로 파고든 것처럼 보입니다 | 굴리는 칸과 가운데 맞추는 칸을 **나눕니다**. 바깥에 `overflow-y-auto`, 안쪽에 `min-h-full flex items-center` |
| **배열을 문자열로 이어붙여 useEffect 의존성으로 쓰기** | 이음쇠로 쓴 공백이 파일 안에서 **NUL 바이트로 깨졌습니다.** 동작은 멀쩡한데 **git 이 그 파일을 바이너리로 봐서 변경 내역이 안 보입니다** | 이어붙이지 말고 **ref 에 같이 담기**. `git show --stat` 에 `Bin ... bytes` 가 보이면 이걸 의심 |
| **고른 표시를 보기 *안에* 넣기** | 그 보기가 높아지며 **아래 보기들이 밀립니다.** 두 번째 탭이 엉뚱한 데 떨어져 오탭 방지가 오탭을 만듭니다 | 목록 **바깥**에 고정 높이로 |
| **게임이 요구하는 것을 자료가 못 대는데 그냥 내기** | ④ 설명하기는 **뜻을 말하는 것이 금지**인데 덱에 `把`(~을)·`被`·`了` 가 그대로 들어 있었습니다. 가리키는 물건도 동작도 없어 **몸짓으로도 못 합니다.** 하나 걸리면 60초 중 20초가 날아갑니다 | 게임을 붙일 때 **"이 게임이 요구하는 것을 못 대는 단어가 973개 중 몇 개인가"** 를 먼저 셉니다. ④는 `canExplain`(품사에 명사·동사·형용사가 있고 뜻에 `~` 가 없을 것)으로 132개를 뺍니다. **몇 개 억울하게 빠지는 것이, 못 낼 문제가 섞이는 것보다 낫습니다** |
| **성적에 매인 명단을 화면에 띄우기** | ⑤ 의 '쉬는 사람' 은 맞혀야만 오르는 명단이라, **12문제가 끝나도록 이름이 안 뜬 사람 = 한 번도 못 맞힌 사람**이 됐습니다. 개인 점수를 안 띄우기로 해놓고 **거꾸로 된 순위표**를 띄우고 있었습니다 | 그리는 방식을 바꿔봐야 소용없습니다. 띄우든 뒤집든 감추든 성적에 매여 있으면 드러납니다. **성적에서 아예 떼어냅니다** — ⑤ 는 차례로 돌아가며 쉽니다.<br>**"이 명단에 없는 것이 무슨 뜻이 되나" 를 묻습니다** |
| **소리가 끝나는 때를 시계로 짐작하기** | `speak()` 은 읽던 것을 **끊습니다.** "2초 뒤에 한 번 더" 로 걸면 2초 안에 못 읽는 단어는 **첫 번째가 잘립니다.** 소리는 부르는 즉시가 아니라 **조금 뒤에** 시작하는데(클라우드 목소리는 훨씬 뒤), 그 시간도 예산을 갉아먹습니다 — 4글자는 기기 안 목소리로도, 3글자는 클라우드 목소리로 잘렸습니다 | **끝났다는 신호**(`onend`)를 쓰고 그 뒤에 쉽니다(`speakTimes`). 신호가 **아예 안 오는 기기**가 있으니 예비 시계를 같이 둡니다.<br>**⚠ 넘어가느라 끊긴 것도 '끝' 입니다** — 그대로 두면 앞 문제의 신호가 뒤늦게 도착해 **새 문제 위에서 앞 단어가 울립니다.** 그만두는 함수를 받아 새 소리 전에 반드시 부릅니다 |
| **여러 형식을 내는 함수에서 한 형식만 주워 담기** | `makeQuiz` 는 형식을 **차례로** 봅니다. 앞 관문(`isTypable` = 뜻이 짧고 하나)이 **제일 쉬운 단어를 먼저 낚아채서**, 뒤에서 `pick-zh` 만 담던 ③ 귀로 잡기에 **어려운 단어만 남았습니다**(973개 중 393개가 사라지고, 남은 것 중 쉬운 단어 0개). 걸러진 게 아니라 **다른 형식으로 나간 것**이라 화면에서는 안 보입니다 | 그 형식만 만드는 함수를 **따로 냅니다**(`makePickZh`). 오답 고르는 부분(`pickWrong`)은 그대로 불러 규칙을 물려받고, **`makeQuiz` 는 안 건드립니다** — 고치면 `/study` 의 문제 배분이 통째로 바뀝니다.<br>**담기 전에 "안 담긴 것은 왜 안 담겼나" 를 한 번 세어봅니다** |
