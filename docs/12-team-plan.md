## 사장님 요청

> 지금은 사용자 각자가 혼자 쓰는 구조인데, **팀으로 같이 모여서 공부하는 기능**이 있으면 좋겠다.
> 팀 단위로 하면 좋을 기능 3~5개를 **좋은 아이디어로만**. 그 밖에 고도화할 것도 같이.

---

## 회의에서 갈린 것 — 이게 제일 중요합니다

### ⚠ 순위표를 만들지 않습니다

제품 기획팀은 "팀원별 푼 개수 · 맞힌 비율 · 연속 일수" 현황판을 냈고,
**학습 설계팀이 반대했습니다.**

- **2~5명짜리 팀에서는 꼴찌가 한 명뿐이고, 매일 자기가 꼴찌인 것을 봅니다.** 그 사람이 제일 먼저 그만둡니다
- 이 사이트는 익명이 아닙니다. 아이디가 실명처럼 박힙니다
- 순위가 실력을 올린다는 근거는 약합니다. 지속률을 올리는 것은 **"오늘 했나 안 했나"** 라는 존재 신호까지입니다

**결론: 남의 숫자를 안 보여줍니다.** 보여주는 것은 ① 오늘 했다/안 했다 ○× ② **팀 전체 합계** 둘뿐입니다.

### ⚠ 팀 기능은 `progress` 를 절대 건드리지 않습니다

이 사이트의 핵심 자산은 **사람마다 다른 복습 일정**입니다.
"별표만 눌러도 그 단어가 오늘의 1번으로 튀어나온" 사고(5회차)와 같은 구조를 또 만들면 안 됩니다.

| 금지 | 왜 |
|---|---|
| 팀 공동 덱 · "이번 주는 다 같이 1~50번" | 사람마다 `due_at` 이 다른데 목록을 강제하면 간격 반복이 아니라 **커리큘럼**이 됩니다 |
| 팀에서 틀린 것을 `wrong_count` 에 더하기 | `weakWords()` 는 `wrong_count > 0` 이면 **무조건** 오답 노트에 올리고, **줄이는 길이 없습니다** |
| 남이 내 진도를 바꿀 수 있게 하기 | 되돌릴 수 없는 값을 남의 손에 |

**지킬 선: 팀은 `attempts` 에만 씁니다.** `/tone` 과 `write` 가 이미 그렇게 되어 있습니다.

### ⚠ 문서 오류 발견

`CLAUDE.md` 에 이렇게 적혀 있습니다.

> **`user_key` 는 브라우저에 저장한 UUID다. 로그인을 만들지 않는다.**

**둘 다 지금은 틀립니다.** 마이그레이션 7(`username.sql`)에서 로그인이 생겼고,
`user_key` 는 **로그인 계정 번호(`auth.uid()`)의 문자열**입니다.
브라우저에서 UUID 를 만드는 코드는 `web/` 전체에 **한 줄도 없습니다.**
옛 구조를 옮겨오던 `claim_progress()` 도 13번에서 **삭제됐습니다.**

→ 팀 작업을 시작하기 전에 이 두 줄부터 고쳐야 합니다. 안 고치면 다음 사람이 없는 구조 위에 설계합니다.

## ★ 팀보다 먼저 해야 하는 것

### G1. 계정 복구 코드

**지금 비밀번호를 잊으면 계정이 영영 닫힙니다.** 관리자가 SQL로 바꿔주는 길밖에 없습니다.

혼자 쓸 때는 감수할 만했습니다. 그런데 **남을 초대하는 순간
"비밀번호를 잊었어요" 가 반드시 옵니다.** 그때 사장님이 Supabase SQL Editor 를 열어야 합니다.

가입할 때 **8자리 복구 코드를 한 번 보여주고**, 잊었을 때 그것으로 재설정합니다.
메일이 없는 상황에서 되는 **유일한 길**입니다. (`profiles` 에 칸 하나 · 하루)

> **팀 기능보다 이게 먼저입니다.** 순서를 바꾸면 남을 들여놓고 문을 못 열어줍니다.

## 팀 기능 5가지

노리는 것은 하나입니다 — **혼자서는 받을 수 없는 피드백.**
"같이 있으면 열심히 한다" 는 근거가 약합니다(익숙한 과제에서만 오르고 어려운 과제에서는 오히려 떨어집니다).

### 1. 팀 만들기 · 초대 코드 · 오늘 나온 사람 — **기반**

이게 없으면 나머지가 하나도 못 섭니다. 그런데 이것만 만들면 값어치가 0이라
**"오늘 나온 사람" 까지 한 덩어리로** 냅니다.

| | |
|---|---|
| **화면** | 홈에 카드 한 장 → 누르면 `/team` 전체 화면 |
| **보여주는 것** | 팀원 아이디 · **오늘 했다 ○ / 안 했다 ×** · **팀 전체 합계**(오늘 우리 팀이 몇 문제) |
| **안 보여주는 것** | 개인별 개수 · 정답률 · 연속 일수 · 오답 노트 |
| **표** | `teams` · `team_members` 2개 |
| **기간** | 이틀 |

**초대 코드** (메일을 못 보내는 제약에서 나온 유일한 답)

| | 정한 것 |
|---|---|
| 길이 | **6자**, `ABC-123` 처럼 끊어 보여주고 저장은 붙여서 |
| 글자 | 헷갈리는 짝(`0 O` · `1 I L` · `5 S` · `8 B` · `2 Z`)은 **한쪽만** |
| 오타 | **서버가 정규화**합니다 — 소문자→대문자, 공백·하이픈 제거. 화면에서만 다듬으면 다른 경로로 어긋난 값이 들어옵니다 |
| 만료 | **없음.** 대신 팀장이 `새 코드 발급`(옛 코드 즉시 무효)과 `가입 잠금` |
| | *만료를 두면 만료된 코드를 되살릴 길이 SQL뿐입니다. 막으려던 것보다 큰 사고를 만듭니다* |
| 재사용 | 여러 명이 같은 코드. 인원 상한 8명 |
| 전달 | **`초대 링크 복사`** — 카톡으로 보내면 옮겨 적는 일 자체가 없어져 오타가 0 |
| 막기 | 코드 틀리기 **1시간에 10번**까지. **서버가** 셉니다 |

### 2. ⭐ 성조 서로 듣고 맞히기 — **이 사이트에서 팀이어야 할 이유가 가장 강한 것**

한 글자를 녹음해 팀에 던지면, 팀원이 듣고 **몇 성인지** 맞힙니다.

| | |
|---|---|
| **왜 혼자서는 안 되나** | **자기 목소리는 뼈를 타고 들려서 남이 듣는 소리와 다릅니다.** 그리고 `pitch.ts` 는 **높낮이만** 재고 자음·모음은 못 봅니다. 사람 귀는 나머지 전부를 봅니다 |
| **왜 HSK인가** | **한국어에는 성조가 없습니다.** 한국인 학습자는 자기가 4성을 냈는지 2성을 냈는지 **감각 자체가 없습니다** |
| **판정하는 쪽도 공부가 됩니다** | 남의 성조를 듣고 맞히는 것이 **그 자체로 내 듣기 훈련**입니다. 팀 기능이 죽는 가장 흔한 이유가 "도와주는 쪽이 지루해서" 인데, 여기엔 그게 없습니다 |
| **덤** | 지금 듣기 연습은 **TTS 한 종류**뿐입니다. 팀원 수만큼 화자가 늘어납니다 |
| **지속성** | **높음.** 매번 새 소리라 소재가 안 떨어집니다 |
| **2명이면?** | **2명이 최적입니다** |

`/tone` 의 🎤 말해보기가 이미 녹음·판정을 하고 있어서, 그 결과를 던지는 자리만 붙이면 됩니다.

### 3. 우리 팀 약점 단어

팀이 합쳐서 제일 많이 틀린 단어 20개 → **`이것만 10개 풀기`**

| | |
|---|---|
| **왜 팀인가** | 혼자 틀린 것은 우연일 수 있지만 **셋이 다 틀린 단어는 자료나 단어 자체에 문제가 있습니다** |
| **★ 개인 숫자는 안 보여줍니다** | 단어별 **합계만**. "누가 몇 번 틀렸나" 는 감시입니다 |
| **표** | 0개 (함수 하나) |
| **기간** | 하루 |

### 4. 한 문제 던지기

방금 내가 틀린 단어를 팀원에게 넘깁니다. 상대는 **자기가 열 때** 봅니다.

| | |
|---|---|
| **왜 팀인가** | **내가 나에게 내는 문제는 이미 아는 문제입니다.** 남이 고른 한 개는 예측이 안 돼서 인출 강도가 다릅니다 |
| **던지는 쪽도** | 자기 약점을 명시화하게 됩니다 |
| **★ 예문을 새로 짓게 하지 않습니다** | 이 프로젝트 규칙입니다. **`data/` 에 있는 단어를 고르는 것**만 됩니다. 오히려 만들기 쉽습니다 |
| **★ 실시간 아닙니다** | 던지고 잊습니다. 상대를 기다리는 화면을 만들지 않습니다 |
| **기간** | 이틀 |

### 5. 예문 읽기 서로 확인 *(여유 있으면)*

소리내어 읽은 것을 던지면 팀원이 **"알아들었다 / 못 알아들었다"**.

지금 `ReadAloud` 는 일부러 **"틀렸다"고 단정하지 않습니다** —
기계가 못 알아들은 건지 내가 틀린 건지 구별할 수 없어서요.
**사람은 그걸 구별합니다.** 지금 남아 있는 미해결 지점을 정확히 메웁니다.

## 팀 아닌 고도화 3가지 (돈 0원 · 지금 자료로)

| | 뭐 | 왜 |
|---|---|---|
| **G2. 약점 지도** | 주제 19개 × 문제 유형 8가지 표. 약한 칸을 누르면 그것만 풀기 | `attempts` 에 유형이 **이미 다 들어 있습니다.** WBS 14번(AI 분석)이 하려던 것의 **80%를 공짜로** 합니다 |
| **G3. 주간 요약** | 지난 7일 며칠 나왔나 · 새로 외운 단어 · 제일 많이 틀린 5개 | 연속 일수 다음으로 계속하게 만드는 힘이 큽니다 |
| **G4. 내 기록 내보내기** | 진도·푼 기록을 CSV 한 장으로 | 계정이 잠기거나 탈퇴할 때의 보험. 제일 쌉니다 |

**G2 를 먼저 하면 AI 분석(14번)을 다시 판단할 수 있습니다.** 공짜로 80%가 채워지면 유료 API를 살지 말지가 분명해집니다.

## 안 하기로 한 것 (그럴듯한데 독)

| 안 함 | 왜 |
|---|---|
| **순위표 · 점수 · 주간 랭킹** | 2~5명이면 **꼴찌가 실명으로 고정**됩니다. 학습 효과 근거도 약합니다 |
| **실시간 대전 · 속도 경쟁** | 속도 압박이 인출을 얕게 만듭니다. 게다가 **6회차 전체를 오탭 막는 데 썼습니다** — 오탭 하나에 복습이 35일 뒤 → 3분 뒤이고 되돌릴 수 없습니다 |
| **연대 스트릭** (한 명 빠지면 다 잃음) | 한 번 끊긴 날 **통째로 이탈**합니다. 아픈 날에 죄책감을 주는 설계 |
| **목표 공개 · 다짐 선언** | **근거가 반대입니다.** 남에게 선언하면 말한 것으로 이미 이룬 느낌이 들어 실행이 줍니다. 효과가 있는 건 **끝난 뒤의 보고**입니다 |
| **팀 채팅 · 댓글** | 학습 효과 0. 신고·차단·삭제가 딸려옵니다. **카톡이 이미 있습니다** |
| **서로의 오답 노트 · 정답률 열람** | 합계는 응원이지만 **상세는 감시**입니다 |
| **푸시 알림** | 남이 내 폰을 울리게 하는 권한은 안 줍니다. 메일은 애초에 불가능 |
| **팀별 단어 자료 편집** | `words`·`examples` 는 읽기 전용이 원칙. 팀마다 뜻이 다르면 검수가 무너집니다 |
| **선생/조교/학생 같은 역할 계층** | 쓰는 사람이 3~8명입니다. **팀장 1명 + 팀원**, 끝 |
| **소셜 로그인 추가** | 지금 아이디 체계(`hong1234@hsk3.local`)와 짝지어진 곳이 여러 군데입니다 |
| **1회용 초대 코드 · 24시간 만료** | 재발송할 수단이 없습니다 |

## 기술 — 지금 구조로 되나

**됩니다. 마이그레이션 파일 1개면 됩니다.**

| | |
|---|---|
| **새 표** | `teams` · `team_members` 둘. (4·5번을 할 때 2개 더) |
| **★ 남의 진도를 RLS 로 열지 않습니다** | **`profiles` 한 표 안에 아이디 · 이메일 · 전화번호가 같이 있습니다.** 팀원에게 그 표를 열면 **연락처가 같이 샙니다.** 그리고 RLS 는 줄만 막지 칸은 못 막습니다(12번 마이그레이션에서 겪은 것). 팀 숫자는 전부 `security definer` 함수가 **합계만** 돌려줍니다 |
| **`v_words` cascade** | **안 걸립니다.** 새 파일이 이름 순서상 한참 뒤입니다 |
| **다시 만들어야 하는 함수** | **`withdraw_account()` 하나.** 탈퇴할 때 팀 명단도 정리해야 합니다 — "다 지웠다" 가 거짓말이 되면 안 됩니다(8번에서 겪은 것). 그러면 이 함수의 최종 정의가 새 파일로 옮겨가므로 `09-handoff.md` 의 표도 같이 고칩니다 |
| **실시간(Realtime)** | **필요 없습니다.** 전부 새로고침으로 됩니다. 켜면 새 나갈 자리가 하나 더 생깁니다 |
| **주의 1** | `user_key` 는 `text`, `profiles.user_id` 는 `uuid` 입니다. 붙일 때 **형변환**이 필요합니다. `progress` 쪽 타입을 바꾸는 건 정책 5개를 다시 써야 해서 권하지 않습니다 |
| **주의 2** | 팀 참여는 `primary key (team_id, user_id)` + **`on conflict do nothing`**. 안 그러면 두 번 눌러 `409` 입니다(이미 겪은 지뢰) |
| **주의 3** | `returns table (...)` 함수는 **칸을 하나만 더해도** 두 번째 실행에서 `cannot change return type` 으로 멈춥니다. 앞에 `drop function if exists` 를 반드시 씁니다 |
| **주의 4** | 탈퇴는 `profiles` 줄을 **안 지우고** `is_active` 만 끕니다. 그래서 `on delete cascade` 를 걸어도 팀 명단은 **자동으로 안 지워집니다.** 함수 안에서 직접 지워야 합니다 |

## 만든다면 이 순서

```
G1 계정 복구 코드          ← 팀보다 먼저. 남을 들이면 문의가 반드시 옵니다
  ↓
1  팀 만들기 + 초대 + 오늘 나온 사람   ← 기반
  ↓
2  ⭐ 성조 서로 듣고 맞히기            ← 이것만 되어도 이 요청은 성공입니다
  ↓
3  우리 팀 약점 단어
  ↓
G2 약점 지도               ← 팀과 상관없이 값이 큽니다. 여기서 AI 분석을 다시 판단
  ↓
4  한 문제 던지기 → 5 예문 읽기 확인 → G3 주간 요약 → G4 내보내기
```

**2번 하나만 되어도 이 요청은 성공입니다.** 나머지는 없어도 되는 것들입니다.
