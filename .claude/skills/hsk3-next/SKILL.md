# 다음 작업 이어가기

사용자는 코딩을 모릅니다. **되묻지 말고 순서대로 진행합니다.**
"다음 거 할까요?" 를 매번 물으면 사용자가 매번 "응" 을 쳐야 합니다. 그건 자율이 아닙니다.

## 1. 지금 어디까지 왔는지 확인

이 순서로 읽습니다.

1. `docs/11-wbs2.md` — **지금 회차의 작업 목록.** 없으면 3번으로
2. `docs/09-handoff.md` — 상태와 **"다시 밟으면 안 되는 지뢰"** 표
3. `docs/10-wbs.md` — 지난 회차 목록 (11이 다 끝났으면 여기로)
4. `git log --oneline -10` — 마지막 커밋이 어느 항목인지

`[ ]` 인 것 중 **제일 위**가 지금 할 것입니다.
사용자가 항목을 지정했으면(`T5 해줘`) 그것부터.

## 2. 한 항목 하는 법

### 시작할 때

- **무엇을 왜 바꾸는지 한 줄** 먼저 말하고 시작합니다
- **한 번에 파일 하나씩** 고칩니다
- 새 라이브러리를 설치해야 하면 **반드시 먼저 묻습니다** (여기서는 멈춰도 됩니다)

### 끝났을 때

1. `npm run build` 로 확인 — 커밋 훅이 어차피 막지만, 먼저 보는 편이 빠릅니다
2. `docs/11-wbs2.md` 에서 `[ ]` → `[x]`, **기록** 칸에 한 줄
3. **커밋.** 메시지는 한국어로, 어느 항목을 왜 했는지

```
T5 · 학습 보기에 병음 작게 (요청 ①)

한자만 보이던 보기(빈칸·한자 고르기)에 병음을 붙였습니다.
pick-ko · pick-py 에는 안 붙입니다 — 소리와 병음이 곧 정답입니다.

Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>
```

4. 사용자에게 **두세 줄로** 알리고 **바로 다음 항목으로 갑니다.** 멈추지 않습니다

## 3. 막혔을 때

1. **3번까지 다시** 해봅니다. 매번 다른 방법으로 — 같은 걸 세 번 하는 건 한 번입니다
2. 그래도 안 되면 `docs/11-wbs2.md` 맨 아래 **"막힌 것 기록"** 에 적습니다
   - 무엇을 하려 했나 · 어떻게 세 번 해봤나 · 무슨 오류인가 · 다음에 뭘 해보면 될까
   - 그 항목은 `[ ]` 로 **남겨둡니다.** 체크하지 않습니다
3. **다음 항목이 막힌 것에 딸려 있으면 같이 건너뜁니다.** 예: T2(병음 코드)가 막히면 T3·T4·T7 도 못 합니다
4. 기록만 커밋하고 **그 다음으로 계속** 갑니다

## 4. 목록이 다 돌면

1. `npm run build` · `npx tsc --noEmit` (web 안에서) · 프로젝트에 있는 검사 명령 전부
2. **막혔던 항목을 다시 시험**합니다 — 그 사이에 고친 것 때문에 풀렸을 수 있습니다
3. WBS 의 **합격 기준**을 하나씩 대조해 숫자로 보고합니다
4. **사람이 눈으로 봐야 하는 것**을 목록으로 드립니다 (브라우저를 띄우는 도구가 없습니다)

## 하지 말 것

- **되묻고 멈추지 않는다.** 새 라이브러리 설치와 되돌릴 수 없는 일(DB 지우기, 강제 푸시)만 예외
- 여러 항목을 몰아서 한 번에 커밋하지 않는다
- 사용자가 확인하기 전에 **"확인했습니다"** 라고 쓰지 않는다. 기계가 확인한 것과 사람이 본 것은 다르다
- `.env.local` 의 내용을 화면에 내지 않는다

## 이 프로젝트에서 특히 조심할 것

`docs/09-handoff.md` 의 지뢰 표를 매번 봅니다. 자주 걸리는 것:

| | |
|---|---|
| `useEffect` 신호에 진도·설정을 넣기 | 답할 때마다 **1번 문제로 되돌아감**. ref 에 담을 것 |
| 마이그레이션을 한 번만 돌려보기 | **두 번째 실행에서만** 터짐 |
| 폰 화면에서 `hidden sm:` 로 숨기기 | 폰에서만 기능이 사라짐 |
| 에러를 안 보고 `data` 만 쓰기 | 신호가 끊기면 "없다" 로 읽힘 |
| 보기·문제에 소리를 붙이기 | **소리가 정답을 알려주는 자리**가 있음 |
