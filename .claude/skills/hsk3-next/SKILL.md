# 다음 작업 이어가기

사용자는 코딩을 모릅니다. **되묻지 말고 순서대로 진행합니다.**
"다음 거 할까요?" 를 매번 물으면 사용자가 매번 "응" 을 쳐야 합니다. 그건 자율이 아닙니다.

## 1. 지금 어디까지 왔는지 확인

이 순서로 읽습니다.

1. **`docs/` 에서 번호가 가장 큰 `*-wbs*.md`** — 지금 회차의 작업 목록
   (2026-08-10 기준 `docs/14-wbs3.md`)
2. 그 문서가 가리키는 **기획서** (예: `docs/13-offline-game.md`) — 왜 그렇게 정했는지가 거기 있습니다
3. `docs/09-handoff.md` — 상태와 **"다시 밟으면 안 되는 지뢰"** 표
4. `git log --oneline -10` — 마지막 커밋이 어느 항목인지

`[ ]` 인 것 중 **제일 위**가 지금 할 것입니다.
사용자가 항목을 지정했으면(`L5 해줘`) 그것부터.

## 2. 한 항목 하는 법

### 시작할 때

- **무엇을 왜 바꾸는지 한 줄** 먼저 말하고 시작합니다
- **한 번에 파일 하나씩** 고칩니다
- 새 라이브러리를 설치해야 하면 **반드시 먼저 묻습니다** (여기서는 멈춰도 됩니다)

### 끝났을 때 — 이 네 가지를 매번

1. **확인** — `npm run build`. 검사 명령이 있으면 같이 (`npm run check:pinyin` 등)
2. **문서** — WBS 에서 `[ ]` → `[x]`, **기록** 칸에 한 줄
3. **커밋** — 한국어로, 어느 항목을 왜 했는지

```
L5 · 성조 체조 (첫 게임)

단어와 뜻만 크게 띄우고 몇 성인지 몸으로 답합니다.
TTS 는 정답 공개 뒤에만 — 먼저 틀면 소리가 곧 정답입니다.

Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>
```

4. **푸시** — `git push origin dev`
   - **`dev` 까지만.** `main` 에는 절대 올리지 않습니다
   - Vercel 이 `dev` 를 보고 알아서 다시 올립니다

그리고 사용자에게 **두세 줄로** 알린 뒤 **바로 다음 항목으로 갑니다.** 멈추지 않습니다.

## 3. 막혔을 때 — 3번 보고 넘어갑니다

**같은 오류를 세 번 고쳤는데 계속 나면 거기서 멈춥니다.**
매번 **다른 방법으로** 세 번입니다 — 같은 걸 세 번 하는 건 한 번입니다.

그 뒤에 할 일:

1. WBS 맨 아래 **`🔴 막힌 것`** 에 적습니다
   - 무엇을 하려 했나 · 세 번 어떻게 해봤나 · 무슨 오류인가 · 다음에 뭘 해보면 될까
   - 그 항목은 **`[ ]` 로 남겨둡니다.** 체크하지 않습니다
2. **다음 항목이 막힌 것에 딸려 있으면 같이 건너뛰고** `⏭ 딸려서 같이 건너뛴 것` 에 적습니다
3. 기록만 커밋·푸시하고 **그 다음으로 계속** 갑니다

## 4. 체크만 하고 넘어가는 세 가지

멈추지 않습니다. **WBS 맨 아래에 적고 계속 갑니다.**

| 표시 | 언제 | 어디에 |
|---|---|---|
| **🔴 막힌 것** | 3번 고쳐도 같은 오류 | `🔴 막힌 것` |
| **🟡 문제** | 돌아가긴 하는데 손봐야 함 (임시로 막아둔 것 · 확인 못 한 것) | `🟡 문제` |
| **💰 유료화** | 무료 요금제로는 안 되는 것을 만났을 때 | WBS 의 `💰` 칸 |

**💰 는 특히 중요합니다.** 사용자가 나중에 이 사이트를 팔 생각입니다.
"이건 무료로 안 됩니다" 를 만나면 **거기서 멈추지 말고** 무료로 되는 만큼만 만들고,
얼마가 드는지·언제 필요해지는지를 적어둡니다.

## 5. 목록이 다 돌면

1. `npm run build` · `npx tsc --noEmit`(web 안에서) · 프로젝트의 검사 명령 전부
2. **🔴 와 🟡 를 다시 시험합니다** — 그 사이에 고친 것 때문에 풀렸을 수 있습니다
3. WBS 의 합격 기준을 숫자로 보고합니다
4. **사람이 눈으로 봐야 하는 것**을 목록으로 드립니다 (브라우저를 띄우는 도구가 없습니다)

## 하지 말 것

- **되묻고 멈추지 않는다.** 새 라이브러리 설치와 되돌릴 수 없는 일(DB 지우기, 강제 푸시)만 예외
- **`main` 에 푸시하지 않는다**
- 여러 항목을 몰아서 한 번에 커밋하지 않는다
- 사용자가 확인하기 전에 **"확인했습니다"** 라고 쓰지 않는다. 기계가 확인한 것과 사람이 본 것은 다르다
- `.env.local` 의 내용을 화면에 내지 않는다

## 이 프로젝트에서 특히 조심할 것

`docs/09-handoff.md` 의 지뢰 표를 매번 봅니다. 자주 걸리는 것:

| | |
|---|---|
| `useEffect` 신호에 진도·설정을 넣기 | 답할 때마다 **1번 문제로 되돌아감**. ref 에 담을 것 |
| 마이그레이션을 한 번만 돌려보기 | **두 번째 실행에서만** 터짐 |
| 폰 화면에서 `hidden sm:` 로 숨기기 | 폰에서만 기능이 사라짐 |
| 에러를 안 보고 `data` 만 쓰기 | 신호가 끊기면 "없다" 로 읽힘 |
| 보기·문제에 소리를 붙이기 | **소리가 정답을 알려주는 자리**가 있음 |
| 버튼·링크 **안에** 버튼 넣기 | 누르면 엉뚱한 것이 선택됨. **형제로** 둘 것 |
| 화면이 바뀌는 자리에 잠금이 없음 | 연타의 두 번째 탭이 새 화면 버튼을 누름. 300ms 무시 |
| 4지선다를 새로 짜기 | 고쳐놓은 사고를 처음부터 다시. **`quiz.ts` 재사용** |
