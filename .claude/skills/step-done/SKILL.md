# 단계 하나를 끝냈을 때

사용자는 코딩을 모릅니다. **다음에 뭘 해야 하는지 스스로 알아낼 수 없습니다.**
그래서 매번 끝에 **붙여넣기만 하면 되는 문장**을 드려야 합니다.

## 언제 쓰나

`docs/10-wbs.md` 의 항목 하나가 **실제로 끝났을 때.** 조건 두 가지를 모두 만족해야 합니다.

1. 코드가 돌아가는 것을 확인했다 (빌드 통과 또는 개발 서버에서 확인)
2. **사용자가 눈으로 봤다고 말했다** — 화면이 바뀌는 기능이라면 필수

화면이 안 바뀌는 작업(기록 남기기 등)은 2번 대신 **실제 데이터로 확인한 결과**를 보여줍니다.

## 순서

### 1. WBS 갱신

`docs/10-wbs.md` 에서
- 그 항목의 `[ ]` → `[x]`
- **기록** 칸에 커밋 번호와 한 줄 요약
- 맨 위 `지금 진행:` 을 다음 번호로

### 2. 커밋하고 푸시

`dev` 브랜치에. 커밋 메시지는 한국어로, 무엇을 왜 바꿨는지.

### 3. 사용자에게 이 네 가지를 알려준다

**① 뭘 했나** — 두세 줄. 전문용어를 쓰면 괄호 안에 쉬운 말로

**② 확인하는 법** — 어디를 눌러 어떻게 보면 되는지. 없으면 "확인할 화면은 없습니다" 라고 분명히

**③ 지금 `/clear` 해도 되는지**
- **해도 됨** — 다음 단계가 지금 한 일과 상관없을 때. 대화가 길어졌으면 권한다
- **하지 마세요** — 다음 단계가 방금 만든 것 위에 바로 얹힐 때. 이유를 한 줄로

**④ 다음에 붙여넣을 문장** — 코드 블록으로. 이것만 복사하면 되게

```
c:\workspace\hsk3-prep 프로젝트를 이어서 할 거야.
docs/09-handoff.md 와 docs/10-wbs.md 를 읽고, WBS N번부터 시작해줘.
```

`/clear` 를 안 해도 될 때는 이렇게:

```
좋아, 다음 N번 진행해줘
```

### 4. 회차가 끝날 때만 추가로

그날 작업을 아예 마칠 때는 `docs/09-handoff.md` 도 갱신합니다. 단계마다 할 필요는 없습니다.

## 하지 말 것

- 사용자가 확인하기 전에 `[x]` 로 바꾸지 않는다
- 다음 단계를 **묻지 않고 시작하지 않는다.** 끝났다고 알리고 멈춘다
- 여러 단계를 한 번에 끝내고 몰아서 보고하지 않는다
